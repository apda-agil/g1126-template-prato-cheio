
# Retrospectiva 3 — Prato Cheio

## Contexto

Na terceira etapa do projeto Prato Cheio, a equipe concentrou seus esforços na integração das alterações, validação dos critérios de aceite, execução de testes e preparação da demonstração final.

O principal objetivo foi verificar se o sistema continuava funcionando após a migração de SQLite para PostgreSQL e identificar pendências para evolução do produto.

## O que funcionou bem

- Organização do trabalho em tarefas e commits individuais.
- Migração da persistência para PostgreSQL.
- Utilização do GitHub Actions para executar testes.
- Separação das regras de negócio da camada de persistência.
- Documentação das decisões arquiteturais por meio de ADRs.
- Preservação do fluxo principal de publicação e aceite de doações.

## O que poderia ter sido melhor

- Planejar a migração do banco com mais antecedência.
- Validar o ambiente de execução antes de iniciar a integração.
- Manter os critérios de aceite atualizados durante o desenvolvimento.
- Registrar evidências de testes a cada alteração.
- Evitar deixar a preparação da demonstração para o final.

## Principais dificuldades

### Ambiente de desenvolvimento

A utilização do PostgreSQL exigiu a configuração de um ambiente de banco de dados.

Foi encontrada uma dificuldade com o Docker Desktop, pois a atualização do WSL dependia de permissões de administrador.

Como alternativa, a equipe utilizou o GitHub Actions para executar os testes em um ambiente com PostgreSQL.

### Migração de banco de dados

A migração exigiu adaptar as consultas SQL e revisar as configurações de conexão, preservando as regras de negócio.

### Validação dos requisitos

A comparação com os critérios da Unidade 1 revelou funcionalidades parcialmente atendidas e outras ainda não implementadas.

Essas pendências foram registradas em `docs/validacao.md`.

## Decisões da equipe

1. Manter PostgreSQL como banco de dados do projeto.
2. Preservar as regras de negócio existentes.
3. Utilizar testes automatizados para verificar regressões.
4. Registrar critérios não atendidos de forma transparente.
5. Priorizar a documentação e a demonstração reproduzível.

## Próximos passos

- Confirmar o CI verde após integrar a Entrega 3.
- Realizar clone limpo em outro computador.
- Executar o roteiro da demo sem ajuda.
- Corrigir problemas identificados na validação.
- Avaliar a implementação do horário de aceite.
- Planejar o painel semanal de doações expiradas.
